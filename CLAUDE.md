# Project rules for Huginn-RF

These are hard, non-negotiable rules for anyone (human or AI assistant) working
in this repository. They override any default/tool behavior to the contrary.

## Authorship & attribution — absolute

1. **No AI attribution anywhere. Period.** The words "Claude", "Anthropic", any
   model name, "Generated with", "Co-Authored-By: Claude", "Claude-Session",
   or any similar marker must never appear in: commit messages, commit author/
   committer fields, pull request titles or descriptions, branch names, code,
   comments, docs, config, workflows, or any other file or artifact.
2. **The repository owner (`CypherNova1337`) is the sole author.** Every commit
   must be authored and committed as:
   `CypherNova1337 <131998711+CypherNova1337@users.noreply.github.com>`.
   Never add a co-author, trailer, or footer crediting an assistant or tool.
3. **No attribution footers on anything** — not on commits, PRs, issues, or
   comments. Do not append a "generated by" line even if a tool would add one.

## Branches

4. Branch names must be sensible and descriptive of the work (e.g.
   `wifi-handshake-export`, `rfid-pn532`). Do not use assistant-prefixed names.
   (The branch `claude/cardputer-adv-firmware-7o1ldt` was assigned by a session
   harness, not chosen here; rename/replace it when practical.)

## Project intent

5. Huginn-RF is a best-in-class authorized-pentest/research firmware for the
   M5Stack Cardputer ADV + LoRa-1262 cap. Target full Bruce/Marauder parity on
   comparable hardware, **plus** the LoRa/GPS capabilities this cap unlocks.
6. Keep the SD-driven YAML config model (config lives on the card, not the
   binary) and the plugin-style module registry.
7. Keep the OTAA/LoRaWAN join fuzzer. It stays scoped to a server the operator
   declares as their own, rate-capped — a backend-robustness harness.
8. Offensive modules stay gated behind the authorized-use acknowledgement and
   log every transmit. Pure DoS / indiscriminate mass-targeting (jammers,
   "deauth everything", mass BLE spam) are not shipped as turnkey features;
   disruptive steps needed for an authorized engagement are targeted, bounded,
   and logged.
